---
title: Releasing
description: Maintainer commands that publish a package or tag the server image.
---

Publish from a clean `main` that matches GitHub. `npm login` stores the npm token in `~/.npmrc`. Store `PYPI_TOKEN` in `~/.zshrc`. Keep both tokens out of the repo and out of `.env`.

Bump `@anumat/js` or `@anumat/engine` with `pnpm changeset` and then `pnpm changeset version`. Bump `anumat-py` with `pnpm bump:anumat:version`. Bump `anumat-engine` with `pnpm bump:engine:version` when you want a patch on that package. `pnpm release:engine-py` publishes that Python version. It does not copy the `@anumat/engine` version.

| Command | Publishes | Tag |
| --- | --- | --- |
| `pnpm release:engine` | `@anumat/engine` on npm | `@anumat/engine@<version>` |
| `pnpm release:engine-py` | `anumat-engine` on PyPI | `anumat-engine@<version>` |
| `pnpm release:anumat` | `@anumat/js` on npm | `@anumat/js@<version>` |
| `pnpm release:anumat-py` | `anumat-py` on PyPI | `anumat-py@<version>` |
| `pnpm release:server` | nothing to a package registry | `server@<version>` |

`pnpm release:engine` builds, runs the tests, prints the `npm pack --dry-run` file list, and waits until you type the version. It then publishes and pushes the tag.

`pnpm release:anumat` builds, runs the tests, prints the npm dry run, and waits until you type the version. It then publishes and pushes the tag.

`pnpm release:anumat-py` builds the wheel, checks that the wheel imports, and publishes with `uv publish`. It then pushes the tag.

`pnpm release:server` reads the version in `apps/api/package.json`, asks you to type that version, and pushes `server@` plus that version. The tag push publishes `ghcr.io/amitmirgal/anumat`.

`pnpm release:engine-py` uses the version in `packages/engine-py`, checks that the documented disposable Postgres is accepting connections at `127.0.0.1:5432`, runs the package tests, and builds one wheel for each platform. Catalog tests need that server (role `anumat` / `anumat`). They recreate only `anumat_engine_parity`. The release script does not start Docker and does not drop `anumat` or `anumat_test`. Start Postgres with the README `docker run` for `anumat-postgres` if the preflight fails. It publishes those wheels with `uv publish`. It creates the local tag `anumat-engine@<version>`. It prints the push lines and does not push. It does not copy or overwrite from `@anumat/engine`.

```bash
git push origin main && git push origin tag anumat-engine@<version>
git push origin main --follow-tags
```

`release:engine-py` tags `anumat-engine@<version>`. `release:anumat-py` tags `anumat-py@<version>`. They publish different packages.

There is no `release:js` command and no `release:py` command.
